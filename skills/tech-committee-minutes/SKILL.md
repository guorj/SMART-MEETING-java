# 吉青技术委员会周例会会议纪要生成

将技术委员会周例会的语音转写原始记录（`说话人N + 时间戳` 格式、高度口语化、含同音错别字）提炼为结构化会议纪要 Markdown。

## 触发方式

Java 后端发送 `/skill:tech-committee-minutes` 指令，附带业务数据：

```
/skill:tech-committee-minutes
meetingId=meeting-002
meetingTitle=技术委员会周例会
meetingType=2
participants=田树清,褚玥,何浩
transcriptLength=12345

---

## 会议转写文本
（转写全文或截断片段）
```

## 执行步骤

1. **（可选）读取近期同类型纪要参考**
   - 调用 `meeting-mysql__mysql_query` 查询最近 1–2 期技术委员会纪要，对齐格式与术语：
     ```sql
     SELECT m.content_markdown, mt.actual_end_time
     FROM int_meeting_minute m
     JOIN int_meeting mt ON m.meeting_id = mt.id
     WHERE mt.preset_type_code = 2
     ORDER BY mt.actual_end_time DESC
     LIMIT 2
     ```
   - 查询失败时跳过，在输出开头注明「未读取历史纪要参考」即可继续。

2. **通读转写全文**，按会议实际讨论顺序识别项目议题、上周进展、本周计划、决策/要求、责任人。

3. **按下方模板与规则生成纪要**，直接输出 Markdown 正文（不要用 JSON 或代码块包裹全文；首行必须是 `# 会议纪要`）。

## 输出约束

- 只输出 Markdown 正文，**不要**保存本地文件；持久化由 Java 后端负责。
- 不要输出 `optimized_minute` 等 JSON 字段。
- 若 MySQL 查询失败，跳过参考步骤继续生成。

## 纪要固定模板

```markdown
# 会议纪要

## 会议基本信息

- **会议主题：** 技术委员会周例会
- **会议时间：** YYYY年M月D日（周X）HH:MM - HH:MM（GMT+08）
- **参会人：** 姓名、姓名、……

## 议题及讨论决策

### 1. 项目标准全称

讨论决策：

1. 上周完成……；本周推进……
2. 决策内容 --负责人

### 2. 下一个项目
```

## 提炼规则

**基本信息**
- 会议主题固定写"技术委员会周例会"；例会惯例在周一举行，日期优先从 meetingTitle / 转写时间戳推断。
- 起止时间从转写头部时间戳与结尾推断；缺失时写"（起止时间待补充）"。
- 参会人从 prompt 中的 participants、转写开头点名、称呼线索（X总/X院长/X部长）及既有常任名单推断；缺席者注明原因（如"董秀红（缺席，未接听）"）。

**议题与决策**
- 议题按会议实际过项目的顺序编号，项目名一律用标准全称（见下方术语表与常设项目清单），转写中的错别字、简称须还原。
- 每个议题下列点浓缩"上周进展 + 本周计划 + 决策/要求"，用精炼书面语替换口语表达；数字、金额、日期、倍率、期限、供应商报价等保持原样，不得估算。
- 条目末尾以 `--姓名` 标注责任人；上级明确提出的要求类条目前加粗 **要求：**。
- 状态表述参考既有纪要习惯：等待验收 / 验收准备 / 正常推进 / 暂停 / 等待外部反馈 / 方向调整 / 待立项。
- 新项目、更名、立项/结项、优先级排序、会议机制调整等结构性变化必须写入纪要。

**噪音过滤与脱敏**
- 开场试音、点名应答、"能听到吗"、设备调试、无关寒暄一律不进纪要。
- 涉及合规敏感话题只保留合规层面的结论性表述，不展开任何操作细节。

**说话人身份推断**
- 通过对话线索定位身份；负责汇报某项目的人通常就是该条目的 `--责任人`。
- 常任参会人名单：田树清、褚玥、何浩、李金雷、涂勇刚、董秀红、唐元洪、贾伟光、谭志强、郭运娇、袁粮森、管小慧、付靖怡、郭儒杰、单承标。无法确定身份时用转写中的称呼（如"田总"）。
