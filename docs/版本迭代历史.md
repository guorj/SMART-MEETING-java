# 智能会议生态 — 版本迭代历史

> 覆盖项目：`smart-meeting-java`、`feishu-scheduled-bot`  
> 文档生成：2026-06-01  
> 版本号规则：从 **0.01** 起按时间顺序递增；同一日期内按依赖关系拆分小版本  
> 数据来源：Git 提交记录、Flyway/schema-upgrade DDL、PRD/开发计划、当前代码与手册

---

## 1. 版本号说明

| 类型 | 含义 |
| ---- | ---- |
| **产品版本（本文）** | `0.01`、`0.02`… 表示两项目联动的功能里程碑 |
| **DDL 内部版本** | `schema-upgrade/v0.x`、`Flyway Vx` 表示数据库结构演进，与产品版本不一一对应 |
| **PRD 版本** | `feishu-scheduled-bot` PRD v1.x；会前对比架构称 **v0.9**（见 §0.22 对应关系） |

两项目共库 MySQL（如 `intelligence`），会前对比、用户映射、Pipeline 等能力跨进程协作。

### 0.11 — 2026-05-23 · 会前事项对比通报（架构 v0.9）

**项目：** smart-meeting-java + feishu-scheduled-bot（**里程碑 M9**）

**架构变更（v0.9 口径）：**

```
触发（Bot Quartz / POST execute）
  → matter-progress-core WeeklyMatterComparisonService
  → 读 preset host_agenda SOURCE + 近 7 日纪要
  → LLM 或 OpenClaw MCP 生成对比 Doc
  → 写回 host_agenda.generated_report_url
  → meeting-server 主持页只读展示（不发群、不调 OpenClaw 会中通报）
```

**实现能力：**

| 组件 | 能力 |
| ---- | ---- |
| **matter-progress-core** | 独立 jar：`WeeklyMatterComparisonService`、JDBC 读写、Legacy LLM / MCP 双路径 |
| **smart-meeting DDL v0.9** | `generated_report_*`、`int_weekly_matter_comparison_job` |
| **feishu-bot Flyway V5** | 共库 job 表；`WeeklyComparisonScheduleService` Quartz 组 |
| **Bot API** | `POST /api/weekly-comparison/jobs/{id}/execute` |

**文档锚点：** `DEVELOPMENT-PLAN.md` M9、`PRD.md` F19、`matter-progress-core/README.md`

## 4. 当前架构快照（0.22）

```text
┌─────────────────────┐     ┌──────────────────────────┐
│ feishu-scheduled-bot│     │ smart-meeting-java        │
│ · PushTask Cron     │     │ · meeting-server :8765    │
│ · POST /api/push    │────▶│ · meeting-admin :8766     │
│ · weekly-comparison │     │ · matter-progress-core jar│
└─────────┬───────────┘     └────────────┬─────────────┘
          │         共库 MySQL           │
          └─────────── intelligence ───────┘
```

| 能力域 | 负责方 | 说明 |
| ------ | ------ | ---- |
| 建会/录音/主持/TTS | meeting-server | 飞书入口、Web 主持页、议题推进 |
| 会前对比 Doc 生成 | feishu-bot + core | Cron 或手动 execute；**不发 IM** |
| 会序确认/回填通知 | meeting-server Pipeline | PRE 步骤；按 owners/leader 发私信 |
| 会后纪要/待办 | meeting-server（可选 bot 推送） | 开关控制；bot 仅作消息通道 |
| 运维配置 | meeting-admin-server | 预设、Pipeline、用户映射 |

### 7.3 里程碑（7.9）交付定义

**必须达成（P0）**

1. 至少 **1 套会务模板** 跑通：建会 → PRE 通知/回填 → 主持+录音 → 纪要 → 待办（可配置降级但链路可演示）。
2. 生产 `application-prod.yml` **显式声明** 纪要/待办/会前/通知开关，附运维组合说明（见 `开关手册.md` §6）。
3. 会前对比：**主持页只读展示**，不发群通报（v0.9 架构不变）。
4. 双项目 `mvn clean test` 通过；共库 DDL 无未执行 upgrade。

**建议达成（P1）**

- 三场景各 1 场验收记录；Bot 定时任务假日/补发策略验证。
- Admin：模板、Pipeline、用户映射可由运维自助，无需改库。

**明确不在 7.9 范围（后置）**

- jq-openclaw 全量 36 人 provisioning、feishu-router 集团试点（并行项目）。
- Bot PRD 二期 F15–F18（富文本/批量/Web UI）整体交付。
- 实时 ASR 默认全开（保持可选，`meeting.asr.realtime-enabled`）。

### 7.3.1 2026-06-07 临时补丁 — open_id 兜底映射（不计入正式版本号）

**背景：** 飞书回调中某用户的 `user_id` 字段为空（仅 `open_id` 有值），导致 `open_dashboard` 等指令被拒绝、无法使用会议管理功能。

**变更内容：**

- `FeishuWebhookController` 新增静态临时映射 `OPEN_ID_TEMP_USER_MAP`（`ConcurrentHashMap<String, String>`）。
- `handleImMessageReceive` 中，当 `resolvePrincipalUserId` 返回空字符串时，按 `sender_id.open_id` 查表，命中则赋临时 `userId = temp_user_<open_id>`。
- 命中时打 WARN 日志，便于追踪与后续清理。
- 代码中以 `TODO` 注释标明「待飞书侧修复该用户身份问题后移除」。

**影响范围：**

- 当前仅映射 1 个用户：`ou_5809ce881ece7dabbccf8402848e32bd`。
- 该用户可正常使用"会议管理"、建会、主持页等全部飞书指令。
- 临时 `userId` 用于会话状态（`startMeetingPendingStore`、`feishuUserLastGroupChatStore`）与日志追踪；不影响数据库持久化（会议、纪要等仍以真实 `user_id` 关联）。

**清理条件：**

- 飞书侧修复该用户身份、`user_id` 字段恢复有值后，移除 `OPEN_ID_TEMP_USER_MAP` 及兜底逻辑。
- 移除时同步更新本文档与 `USER-MANUAL.md`。
