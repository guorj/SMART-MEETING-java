# 混合参会检点 — 用户手册

本文档面向 **会务/运营**、**会议主持**、**线下参会人**、**线上参会人** 及 **现场录音操作员**，说明「线下点名 + 线上接入盘点」的完整使用方式。

技术策略摘要见 [混合参会-音频与检点策略.md](./混合参会-音频与检点策略.md)。

---

## 1. 产品简介

智能会议系统支持 **同一场会混合线下与远程参会**。检点规则如下：

| 参会方式 | 如何记为「已到」 | 是否需要麦克风 |
|----------|------------------|----------------|
| **线下** | AI 主持 **逐一点名**，现场人员对着 **会议室单麦** 语音答到（如「答到」「在」） | 仅现场操作员设备推流 |
| **线上** | 打开 **个人入会链接**，页面自动登记到场 | **不需要**；线上链接禁止向服务器推流 |

```text
开会 → 线上盘点（等待远程同事打开链接）→ 线下点名（仅线下名单）→ 进入议题
```

**重要原则**

- 应到名单以 **`int_meeting_participant`（参会人表）** 为准；创建会议时必须正确标记 `OFFLINE` / `ONLINE`。
- 线上 **不能** 使用共用的「录音页链接」代替个人链接，否则系统无法区分是谁到场。
- 混合会场 **仅允许一路现场音频** 进入转写；远程同事只听会、不推流。

---

## 2. 角色与职责

| 角色 | 主要操作 | 使用入口 |
|------|----------|----------|
| **会务/发起人** | 创建会议、维护参会人及线上线下属性 | 飞书机器人 / Web 选会页 |
| **AI 主持（主持页）** | 自动/手动开始检点、查看双轨名单、推进议题 | 主持会议页 `host-meeting.html` |
| **现场录音操作员** | 打开录音页、拾音、结束会议 | 群内「会议已开始」卡片中的录音链接 |
| **线下参会人** | 被点名后靠近主持麦答到 | 无需单独打开网页 |
| **线上参会人** | 打开飞书单聊中的 **个人入会链接** 完成到场登记 | `/join/{会议ID}?token=…` |

## 3. 会前准备（运维/会务）

### 3.1 数据库

生产库需已包含参会人扩展字段（新库可直接执行 `meeting-server/src/main/resources/schema.sql`；已有库请对 `int_meeting_participant` 执行增量 DDL）：

- `attendance_mode`：`OFFLINE`（默认）或 `ONLINE`
- `checked_in_at`：到场时间
- `check_in_source`：如 `AUTO_ONLINE`、`ROLL_CALL`

### 3.2 服务配置

| 配置项 | 环境变量示例 | 说明 |
|--------|--------------|------|
| 公网访问地址 | `BASE_URL` | 须为飞书与参会人浏览器可访问的 **HTTPS** 地址，用于生成入会/录音链接 |
| 线上盘点等待时长 | `MEETING_HOST_ROLL_CALL_ONLINE_INVENTORY_SEC` | 默认 **60** 秒；结束后自动进入线下点名 |
| 每人答到窗口 | `MEETING_HOST_ROLL_CALL_WINDOW_SEC` | 默认 12 秒（线下） |
| AI 主持总开关 | `MEETING_HOST_ENABLED` | 默认 `true` |

### 3.3 飞书应用

- 机器人需具备向 **群聊**、**用户单聊** 发送消息/卡片的权限。
- 线上个人链接通过 **单聊** 推送；参会人 `userId` 须为飞书 **`open_id`**，否则无法自动收到链接。

## 4. 创建会议并标记线上线下

### 4.1 通过飞书创建（常见）

1. 在群内发送 **「开始会议」** 或点击机器人菜单，在浏览器 **选会页** 选择会议类型并创建。
2. 会议创建并启动后，群内会收到 **「智能会议已开始」** 卡片（含现场 **录音页** 链接）。
3. 若参会人列表中有人标记为 **线上**，系统会向该人飞书 **单聊** 发送 **「线上到会确认」** 个人卡片。

> **注意**：通过纯文字指令 `开始会议 主题:… 参会人:张三,李四` 创建的参会人，默认全部为 **线下**，且 `userId` 可能为占位值，**无法** 自动推送个人链接。混合会请务必使用 Web 选会页或 API，并填写正确的飞书 `open_id`。

### 4.2 通过 API 创建（推荐混合会）

创建会议时在 `participants` 中指定每位参会人：

```json
{
  "title": "集团月度经营分析会",
  "presetTypeCode": 1,
  "participants": [
    { "userId": "ou_xxxx", "name": "张三", "attendanceMode": "OFFLINE" },
    { "userId": "ou_yyyy", "name": "李四", "attendanceMode": "ONLINE" },
    { "userId": "ou_zzzz", "name": "王五", "attendanceMode": "ONLINE" }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `userId` | 线上必填 | 飞书 `open_id`，用于签发个人 JWT 与单聊推送 |
| `name` | 是 | 显示姓名（主持播报、名单展示） |
| `attendanceMode` | 否 | `OFFLINE`（默认）或 `ONLINE` |

### 4.3 查询/补发个人链接（会务）

会议进行中或结束后，可由后台或集成方调用：

`GET /api/v1/meetings/{meetingId}/participant-links`

返回参会人列表；`attendanceMode=ONLINE` 的条目含 `joinUrl`，可复制发给未能收到飞书单聊的同事（注意链接与个人绑定，勿在群内公开张贴）。

## 5. 会议当天流程

### 5.1 时间线总览

```text
[发起人] 飞书创建并启动会议
    ↓
[操作员] 打开录音页，允许麦克风，保持推流
    ↓
[线上同事] 收到单聊「个人入会链接」→ 打开 → 自动「已到会」
    ↓
[主持页] 开场播报结束 → 自动进入「线上盘点」（默认 60 秒）
    ↓
[主持页] 盘点结束 → 「线下点名」：仅 OFFLINE 人员被 TTS 点名
    ↓
[线下同事] 听到自己姓名后，对着现场麦说「答到」
    ↓
[主持页] 检点结束 → 自动/手动进入下一议题
```

### 5.2 现场录音操作员

1. 打开群内卡片中的 **录音页**（仅 **一条** 链接，由发起人/操作员使用）。
2. 允许浏览器使用麦克风，保持页面在前台直至会议结束。
3. 点击 **「结束会议」** 生成纪要（飞书发送「结束会议」为备用方式）。

**请勿** 将录音页链接发给线上同事代替个人入会链接。

### 5.3 线上参会人

1. 在飞书 **与机器人的单聊** 中找到 **「📲 线上到会确认」** 卡片。
2. 点击 **「打开个人入会链接」**（或复制链接到浏览器）。
3. 页面标题为 **「线上到会确认」**，打开后自动登记，显示 **「已到会」** 及登记时间。
4. 登记成功后 **可关闭页面**；无需麦克风，也不会采集您的音频。
5. **请勿转发** 个人链接给他人，否则可能误记他人到场。

若未收到单聊卡片：

- 确认会务创建会议时已设置 `attendanceMode: "ONLINE"` 且 `userId` 为您的飞书账号。
- 联系会务通过 `participant-links` 接口获取您的 `joinUrl`。

### 5.4 线下参会人

1. 无需打开网页。
2. 听到 AI 主持播报 **「请 XXX 答到」** 后，在 **主持麦克风附近** 清晰回答「答到」「在」等。
3. 主持页名单会显示 `[线下]` 及状态「已到」。

## 6. 主持会议页 — 检点操作说明

打开主持会议页（会务类型 1～5 且已配置应到名单时，**开场播报结束后会自动进入检点**）。

### 6.1 检点阶段

| 阶段（界面文案） | 含义 |
|------------------|------|
| **线上盘点中** | 等待远程同事打开个人链接；名单显示 `[线上]`，已到显示「已到(线上)」 |
| **线下点名中** | 仅对 `[线下]` 人员逐一点名、等待答到 |
| **检点已结束** | 本轮完成，可再次点击「开始检点」发起新一轮 |

### 6.2 名单展示

- 每条记录标注 **`[线上]`** 或 **`[线下]`**。
- 线上未到：状态 **「待打开链接」**。
- 线下未到：状态 **「待答到」**；当前点名行高亮。

### 6.3 按钮

| 按钮 | 说明 |
|------|------|
| **开始检点** | 会议进行中且当前未在检点时可点击；发起新一轮（先线上盘点，再线下点名） |
| **跳过当前** | 仅在 **线下点名中** 可用，跳过当前待答到人员 |

### 6.4 与议题的关系

- 若第一议题为「检点」类，检点结束后系统可 **自动进入下一议题**。
- 单麦、无声纹：系统按 **播报顺序 + 现场定稿语音** 判定答到，不验证说话人身份。

## 7. 飞书消息说明

| 消息 | 接收人 | 内容 |
|------|--------|------|
| 会议已开始 | 群聊 | 主题、时间、**现场录音页**（操作员用） |
| 线上到会确认 | 每位 `ONLINE` 且有效 `open_id` 的用户单聊 | **个人入会链接**（按钮打开） |

群内 **不会** 张贴所有人的个人链接，避免泄露与误用。

## 8. 常见问题

### Q1：线上同事打开了录音页，为什么没记为已到？

录音页是 **现场操作员** 用的共用链接，不含个人身份。线上同事必须使用 **个人入会链接**（`/join/...`）。

### Q2：线上同事没收到单聊卡片？

常见原因：

- 创建时未设 `attendanceMode: "ONLINE"`；
- `userId` 不是飞书 `open_id` 或为空；
- 通过「开始会议 参会人:姓名」文字创建，仅有占位 `userId`。

处理：用 API 修正参会人数据，或通过 `participant-links` 获取 `joinUrl` 人工发送。

### Q3：远程同事被点名喊「请答到」？

说明该人被登记为 **线下**。请将会前数据改为 `ONLINE`，并重新创建或更新参会人后再开会。

### Q4：线上盘点时间不够？

请会务提前通知远程同事 **开会前 5 分钟** 留意飞书单聊。运维可调大 `MEETING_HOST_ROLL_CALL_ONLINE_INVENTORY_SEC`（如 120）。

### Q5：多人同时打开录音页会怎样？

音频 WebSocket **同一会议仅保留一个连接**，后打开者会顶掉先打开者。现场务必只保留 **一台操作员设备** 推流。

### Q6：个人链接可以转发吗？

**不建议。** 转发可能导致他人被误记为您本人到场。链接含短期 JWT，过期后需重新获取。

### Q7：纯线上会议（无线下人员）可以吗？

可以。线上盘点结束后若无线下待点名人员，检点会直接进入 **结束** 状态。

## 9. 管理员附录

### 9.1 相关 API

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/v1/meetings/{id}/check-in` | 线上到场登记；请求头 `Authorization: Bearer {个人JWT}` |
| `GET` | `/api/v1/meetings/{id}/participant-links` | 查询参会人及个人 `joinUrl` |

### 9.2 页面路径

| 路径 | 用途 |
|------|------|
| `/join/{meetingId}?token=…` | 线上个人到会确认（无推流） |
| `/rec/{meetingId}?token=…` | 现场录音/推流（操作员 JWT，`can_push_audio=true`） |
| 主持会议页 | AI 主持、检点、议题（需主持 JWT） |

### 9.3 检点状态（主持端 `host_state.rollCall`）

- `phase`：`ONLINE_INVENTORY` → `OFFLINE_ROLL_CALL` → `DONE`
- `people[].attendanceMode`：`OFFLINE` | `ONLINE`
- `people[].checkInSource`：如 `AUTO_ONLINE`、`ROLL_CALL`、`TIMEOUT`、`SKIP`

## 10. 快速检查清单

**会务（会前）**

- [ ] 生产库已升级 `attendance_mode` 等字段
- [ ] `BASE_URL` 为公网 HTTPS
- [ ] 每位线上参会人已设 `ONLINE` + 正确 `open_id` + 姓名

**现场（会中）**

- [ ] 操作员已打开 **录音页** 并保持单连接推流
- [ ] 主持页已启动，开场后进入检点
- [ ] 线上同事已在盘点窗口内打开 **个人链接**

**线上同事**

- [ ] 已打开飞书单聊中的个人入会链接并看到「已到会」
- [ ] 未使用录音页、未向浏览器授权麦克风（除非您同时是操作员）
