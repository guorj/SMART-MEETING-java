## 一、产品概述

### 1.1 一句话描述

让 AI 代替人工主持人，在独立会议空间中按预设议程全语音驱动会议流程，飞书只承担「会前通知 + 会后交付」的桥梁角色。

### 1.2 物理形态

AI 主持人没有独立硬件。它借用会议现场已有的两样东西：

| 物理载体 | 对应功能 | 线下 | 线上 |
|----------|---------|------|------|
| **音箱**（或线上音频流） | 口：TTS 语音播报 | 会议室音箱 | 音频混流推送到每人耳机 |
| **屏幕**（或浏览器） | 脸：Web 会议页面 + 虚拟形象 | 投屏大屏 | 每人浏览器窗口 |

```
线下会议室场景：

  ┌──────────────┐       ┌─────────────────────────┐
  │              │       │                         │
  │   🔈 音箱     │       │  📺 投屏 Web 页面        │
  │              │       │                         │
  │  "现在进入    │       │  ┌──────┐               │
  │   议题二…"    │       │  │ 🤖   │ ← 虚拟形象    │
  │              │       │  └──────┘               │
  │              │       │  ▶️ 议题二  ⏰ 剩 8:30   │
  └──────────────┘       └─────────────────────────┘
          ↑                       ↑
          │         AI 主持人       │
          └───────────┬────────────┘
                      │
              同一台服务器/设备
```

**设计意图**：零硬件依赖，部署零成本。真人主持也是用嘴说话+用屏幕放 PPT，AI 主持人的「嘴」是音箱、「翻 PPT 的手」是 Web 页面自动更新，做的事完全一致。

### 1.3 线上/线下兼容性

**会议发言不需要排队，开麦即可发言。线上同样兼容：**

| 对比维度 | 线下 | 线上 | 差异 |
|----------|------|------|------|
| 音频输入 | 会议室单路混音（约定一次仅一人发言） | 可多路（每人一路，约定一次仅一人发言） | 线上单路更清晰，远场混响通常更轻 |
| AI 主持人语音 | 会议室音箱播放 | 音频混流推送到每人 | 仅音频层多流接入，逻辑不变 |
| Web 会议页面 | 投屏大屏 | 每人浏览器 | 完全相同 |
| 发言人/声纹 | 单路下依赖 ASR+声纹；多路下可按流绑定参会人 | 多路下可按用户/流标注，可不依赖声纹 | 产品约定**无多人同时说话**，不要求叠话分离 |
| 签到点名 | TTS + ASR | TTS + ASR | 完全相同 |

**结论**：线上/线下在「自由开麦、不排队」上一致；在**不同时发言**前提下，单路或多路均可支撑发言人标注与会控逻辑，无需为「多人叠话」单独做语义分支。

### 1.6 用户痛点

| 痛点 | 现状 | 影响 |
|------|------|------|
| 会议需要专人主持 | 每次会议要安排一个人做主持人 | 占用人力资源，主持人无法专注参会 |
| 主持质量参差不齐 | 不同人风格差异大，时间控制松紧不一 | 会议效率不稳定 |
| 时间不可控 | 经常超时、议题讨论拖沓 | 打乱后续安排 |
| AI 主持人感知薄弱 | 只有声音没有形象，缺乏存在感 | 参会人不易建立对 AI 主持的认知和信任 |

### 1.7 产品价值

- **释放人力**：每场会议节省 1 个主持人角色（70-80% 主持工作量由 AI 承担）
- **沉浸参会**：会议过程中无需分心操作飞书，信息全通过语音传递
- **流程标准化**：所有会议按统一节奏推进，不因人而异
- **时间可控**：全语音计时提醒，到时播报；**不自动**进入下一议题或结束会议（由发起人 Web 手动推进/结束，与配置默认一致）
- **有形的 AI 主持**：虚拟形象+口型同步，让参会人明确感知到「谁在主持会议」

## 三、用户故事

### 3.1 MVP（第一阶段）

#### US-01：作为会议发起人，我希望在飞书上提供议程模板后，AI 主持人能在会议中自主推进所有议题

**验收标准**：
- 议程模板与会议匹配，有默认标准模板，模板在数据库中（议程设置 + 时长 + 顺序 + 会议总时长）
- 会议开始后，AI 主持人按顺序逐个推进议程
- 当前议程时间到时自动播报，不自动切换到下一议题
- 会议总时间到时自动播报，不结束
- Web 页面实时显示当前议程和议程进度
- 发起人可在 Web 页面手动暂停/恢复/跳转

#### US-02：作为参会人，我希望能听到 AI 主持人的语音提醒，而不是低头看手机

**验收标准**：
- AI 主持人语音播报所有时间提醒（会议级/议程级）
- 提醒时间点可配置
- 议题时间到 → 语音播报，不自动推进
- 会议时间到 → 语音播报，不自动结束
- Web 页面同步显示倒计时

#### US-03：作为参会人，我希望在屏幕上看到一个虚拟主持人形象，让我明确感知「谁在主持会议」

**验收标准**：
- Web 页面始终显示 AI 主持人虚拟形象（2D 头像/半身像）
- TTS 播报时，虚拟形象口型同步（张嘴/闭嘴跟随语音节奏）
- 不同场景切换不同表情：开场微笑、提醒时眨眼、时间紧张时微微皱眉
- 不播报时形象静止但不消失，维持存在感

#### US-04：作为参会人，我希望能在一个 Web 页面上看到会议的所有实时状态

**验收标准**：
- Web 页面显示：虚拟主持人形象（口型同步）
- Web 页面显示：当前议程、议程剩余时间、会议总剩余时间
- Web 页面显示：当前发言人（由声纹识别自动标注）
- Web 页面显示：议程进度（已完成/进行中/待开始）
- 页面状态实时更新，延迟 ≤ 2 秒

### 3.2 完整版（第二阶段）

#### US-05：作为会议发起人，我希望会前 10 分钟飞书自动推送参会人盘点卡片

**验收标准**：
- 会议开始前 10 分钟，飞书群自动推送盘点卡片
- 卡片显示：参会人名单、声纹注册状态、上次待办完成情况
- 参会人点击卡片「签到」按钮完成签到
- 卡片中有「进入会议」按钮，点击跳转到 Web 会议页面

#### US-06：作为参会人，我希望会议开始时 AI 主持人进行语音点名签到

**验收标准**：
- 会议开始 AI 语音播报：「现在开始点名签到」
- 虚拟形象同步播报，表情切换为点名模式
- 逐一播报参会人姓名：「张三，请回应到」
- 参会人回应「到」→ ASR 识别 → 自动标记签到
- 点名结束播报签到统计
- Web 页面实时显示签到状态
- 未回应的人支持手动标记签到

#### US-07：作为参会人，会议过程中我不需要打开飞书，所有信息通过语音和 Web 页面获取

**验收标准**：
- 会议全程不向飞书群推送任何消息/卡片
- 所有提醒通过 TTS 语音播报
- 所有状态通过 Web 页面查看
- 虚拟形象始终可见，播报时口型同步

#### US-08：作为参会人，会议结束后飞书自动推送纪要和待办，我不需要手动操作

**验收标准**：
- 会议结束，飞书群自动推送结构化纪要文档
- 飞书群自动推送提取的待办事项清单（推送到具体责任人）
- 飞书群自动推送签到统计
- 推送在会议结束后 30 秒内完成

### 3.3 下一版本 — 会控增强（V1.2 产品迭代）

#### US-09：作为会议发起人，我希望当前议题时间到后由系统询问是否结束本议题；若讨论尚未结束，选择继续后议程能自动延长而不必当场改模板

**验收标准**：

- 当前议题预设时长耗尽时：🔊 TTS 播报「本议题时间已到」类提示，且 **Web 与 TTS 侧同步弹出确认**（如「是否结束本议题？」），**不自动**进入下一议题、**不自动**结束会议（与 V1.0/V1.1 一致）。
- 发起人选择 **结束本议题**：进入与现网一致的流程（例如高亮「下一议题」或保持仅手动「下一议题」，以 V1.0 验收为准）。
- 发起人选择 **不结束（继续讨论）**：当前议题 **自动延长**一段可配置时长（如每次 +5 分钟），议题倒计时与提醒逻辑基于**延长后的结束时刻**重新计算；可配置 **单次延长步长**、**同一议题最多自动延长次数**（防止无限拖堂）。
- 若发起人在超时未操作：需有明确默认策略（建议：**视为继续讨论并自动延时一次** 或 **保持等待直至手动选择**），写入配置并在产品说明中公示。
- **本期不做**：会议总时长耗尽时的「是否结束整场会议」询问与总倒计时自动延时（总时长仍仅为提醒，见 4.2.2）。

### 4.2 功能详细说明

#### 4.2.1 议程管理

**议程来源**：会议发起人在飞书上提供

**议程模板格式**：
- 议题名称
- 预设时长（分钟）
- 顺序（自动排序）
- 会议总时长

**交互流程**（会中脱离飞书）：
```
发起人在飞书提交议程模板
    ↓
AI 主持人接收并初始化议程
    ↓
会议开始 → AI 语音播报议程概览（虚拟形象口型同步）
    ↓
逐议题推进：
  🔊 播报：「现在进入议题X：XXX，预计X分钟」
  → 讨论进行中（开麦即可发言，无需排队；**约定不同时多人发言**）
  → ⏰ 到时提醒 → 🔊 播报：「议题X时间到」
  → **不自动**进入下一议题；发起人于 Web 点击「下一议题」后再进入下一项
    ↓
全部议题完成（含手动跳过）→ 🔊「会议结束」（**结束会议**按钮或流程配置触发的结束动作）
```

**状态流转**：
```
待开始(PENDING) → 进行中(RUNNING) → 已完成(COMPLETED)
                                    → 已跳过(SKIPPED)
```

**Web 页面展示**：议程进度列表 + 当前议题高亮 + 各议题耗时

#### 4.2.2 计时提醒（纯语音）

**核心原则**：会中不通过飞书推送任何提醒，全部用 TTS 语音播报。播报时虚拟形象口型同步。

| 层级 | 触发条件 | 播报内容示例 | 默认时间点 |
|------|----------|-------------|-----------|
| 会议级 | 剩余 N 分钟 | 「会议还剩 N 分钟」 | 10分钟、5分钟 |
| 议题级 | 剩余 N 分钟 | 「当前议程X还剩 N 分钟」 | 3分钟 |

**到期行为（当前 V1.0 / V1.1 已实现范围）**：
- 议题时间到 → **仅** TTS + Web 状态提醒，**不**自动进入下一议题
- 会议总时间到 → **仅** 提醒，**不**自动结束会议

**到期行为（下一版本 V1.2，见 US-09）**：
- 议题时间到 → 在以上提醒基础上，增加 **「是否结束本议题」** 的确认（语音引导 + Web 按钮）；选 **不结束** → 对**当前议题**按配置 **自动延长**剩余时长（步长、最大次数可配）；选 **结束** → 不延长，由发起人按需点击「下一议题」等既有控件。
- **会议总时间到**：**本期仍仅** TTS + Web 提醒，**不**增加询问与自动延时总倒计时（该能力本期不做，与 V1.0 一致）。

**可配置项**（全部在配置文件中）：
- 各层级提醒时间点
- 是否自动推进议题，默认否
- 是否自动结束会议，默认否
- （V1.2）议题到期确认开关、单次延时步长（分钟）、同一议题最大自动延时次数
- （V1.2）确认弹窗/语音轮询超时后的默认行为（继续并延时一次 / 仅等待手动）

#### 4.2.3 发言模式：自由发言

**会议发言不需要排队，开麦即可发言。**

**音频与发言人前提（审核澄清）**：

- 输入可为**单路**（如会议室混音）或**多路**（如远程每人独立音频流）；技术实现按部署选型，不在此 PRD 强制唯一形态。
- 会议**约定不出现多人同时说话**（无叠话）；不要求 ASR/声纹具备多人叠话分离能力。
- **当前发言人**：线下/单路时以 **ASR + 声纹** 自动标注为主；远程多路且流与参会人已绑定时，可按 **流/用户 ID** 标注，**可不启用声纹**。Web 页面实时展示。
- AI 主持人仅负责议程和时间管理，不干预发言顺序。
- 发起人可在 Web 页面手动控制全体静音/解除静音。

**线上相对优势（在上述前提下）**：多路时说话人与流一一对应，标注链路更简单；单路时仍依赖声纹与拾音质量。

#### 4.2.4 虚拟主持人形象

**设计目标**：让参会人明确感知到「谁在主持会议」，避免 AI 主持人沦为无存在感的背景音。

**MVP 方案**（第一档：轻量版）：

- **形态**：2D 虚拟头像/半身像，嵌入 Web 会议页面左上角或中央上方
- **口型同步**：TTS 播报时嘴部动画跟随语音节奏（张嘴-闭嘴），不播报时静止但形象保持可见
- **表情切换**：
  | 场景 | 表情 | 说明 |
  |------|------|------|
  | 开场 | 😊 微笑 | 友好开场 |
  | 议题推进 | 😐 正常 | 平稳播报 |
  | 时间提醒（5分钟）| 😗 眨眼提醒 | 引起注意 |
  | 时间紧急（3分钟）| 😟 微皱眉 | 传递紧迫感 |
  | 点名签到 | 🎙️ 注视 | 专注认真 |
  | 会议结束 | 😊 微笑点头 | 圆满收尾 |

- **技术方案**：Lottie 动画 或 Live2D/Cubism 模型 + TTS 音频联动，1-2 天可集成

**标准版方案**（第二档，V1.1 可选）：

- 半身/全身虚拟形象，可选角色（男/女/中性）
- 手势动作：开场举手示意、议题切换时伸手引导、结束时鞠躬
- 视线跟随：根据当前发言人方向微调
- 可定制：换装、发型、公司 logo 配饰

**未来版方案**（第三档，V2+）：3D 数字人实时渲染，光影自然，情感表达根据会议氛围自动调节。

#### 4.2.5 点名签到

**飞书会前签到**（会前 10 分钟）：
- 飞书群推送盘点卡片 → 参会人点击「签到」
- 此为本阶段唯一的飞书交互

**会中语音点名**（会议开始后，脱离飞书）：
```
🔊「现在开始点名签到」（虚拟形象切换为点名表情）
    ↓
🔊「张三」
    → 张三说「到」→ ASR 识别 → ✅ 自动标记
    ↓
🔊「李四」
    → 李四无回应 → ⏳ 标记未签到
    ↓
逐个点名完成
    ↓
🔊「签到完成。应到 5 人，实到 4 人，李四未到」
    ↓
Web 页面显示签到状态
```

**签到方式**：
| 方式 | 说明 |
|------|------|
| 飞书卡片签到 | 会前 10 分钟飞书卡片签到 |
| 语音回应签到 | 会中点名回应「到」 |
| 手动确认签到 | Web 页面手动标记 |

#### 4.2.6 TTS 语音播报

**引擎**：采用**讯飞开放平台「在线语音合成」流式 WebSocket API**（文档与计费说明见 [在线语音合成 API](https://www.xfyun.cn/doc/tts/online_tts/API.html?target=price)）。服务端合成音频推送至 Web 主持页播放，并与虚拟形象口型联动；异常时可降级为 Web 文字提示（见非功能需求）。

**全场景播报表**：

| 场景 | 播报内容示例 | 触发时机 | 虚拟形象配合 |
|------|-------------|----------|-------------|
| 🎙️ 点名签到 | 「现在点名签到。张三」 | 会前点名 | 专注注视 |
| 📊 签到结果 | 「签到完成。应到 5 人，实到 5 人」 | 点名结束 | 点头 |
| 🎬 开场 | 「会议开始。今天议程共 X 项，预计 X 分钟。第一项……」 | 会议启动 | 微笑，口型同步 |
| 📋 议程推进 | 「现在进入议题 X：XXX，预计 X 分钟」 | 议题切换 | 正常，口型同步 |
| ⏰ 时间提醒 | 「议题 X 还剩 3 分钟」 / 「会议还剩 5 分钟」| 计时触发 | 表情按紧急度切换 |
| 🏁 会议结束 | 「会议结束。纪要已生成，待办已提取。感谢各位」 | 会议结束 | 微笑点头 |

**语音质量要求**：
- 清晰可辨，语速 1.0x（可配置）
- 音量适中（可配置）
- 音色自然不机械

## 六、非功能需求

### 6.1 性能要求
- Web 页面状态更新延迟 ≤ 2 秒
- TTS 语音播报延迟 ≤ 3 秒（从触发到开始播放）
- 虚拟形象口型同步延迟 ≤ 200ms（与 TTS 播报对齐）
- 语音签到回应识别延迟 ≤ 1.5 秒
- Web 页面首次加载 ≤ 3 秒

### 6.2 可用性要求
- Web 页面核心操作不超过 1 次点击
- 语音播报清晰可辨，语速/音量可调
- 虚拟形象始终可见，不因非播报状态消失
- 异常处理友好（网络中断、TTS 故障降级为 Web 文字提醒+虚拟形象静止，故障恢复后立马回复到正常状态）

### 6.3 可配置性
- 计时提醒时间点
- 是否自动推进议题
- TTS 开关
- TTS 语速/音量/音色
- 虚拟形象开关（可关闭只保留语音）
- 点名签到开关
- （V1.2，见 4.2.2 / US-09）**仅当前议题**：到期确认开关、单次延时步长、同一议题最大自动延时次数、确认超时默认策略

### 6.4 兼容性
- 基于 smart-meeting-java 现有框架
- 复用 ASR / 声纹 / 待办 / 纪要模块
- Web 页面独立部署，不依赖飞书环境
- 线下：投屏大屏 + 会议室音箱
- 线上：每人浏览器 + 音频混流
- 与现有「观众模式」并存（可选开启主持人模式）

### 6.5 会中零飞书保证
- 会议开始后，系统**禁止**向飞书群发送任何消息/卡片
- 会议结束后，系统**自动恢复**飞书推送能力
- 此规则在代码层面强制约束

## 八、版本规划

### V1.0 — MVP（预计 6 天）

**目标**：在 Web 页面 + 语音环境中跑通一场基础 AI 主持会议，带虚拟形象，会议过程零飞书。

| 功能 | 说明 | 工作量 |
|------|------|--------|
| 议程管理 | 接收模板 + 按序推进 + 暂停/恢复/跳转 | 1天 |
| 计时提醒 | 两级倒计时（会议+议题）+ TTS 语音播报提醒 | 1天 |
| 虚拟主持人形象 | 2D 头像 + 口型同步 + 场景表情切换 | 1.5天 |
| TTS 语音播报 | 全场景播报引擎（开场/议题/提醒/结束） | 1.5天 |
| Web 会议页面 | 虚拟形象 + 议程看板 + 签到状态 + 倒计时 + 发起人控制 | 1天 |

**MVP 能做**：语音驱动的完整会议流程，Web 页面带虚拟形象口型同步，自由发言模式，全程不碰飞书。

**MVP 不做**：会前盘点、点名签到、声纹标注当前发言人、飞书会后推送。

### V1.1 — 完整版（预计 4 天，累计 10 天）

**目标**：飞书会前签到 + 语音点名 + 声纹标注发言人 + 飞书会后交付，闭环完整体验。

| 功能 | 说明 | 工作量 |
|------|------|--------|
| 飞书会前盘点卡片 | 推送 + 签到 + 跳转链接 | 1天 |
| 语音点名签到 | TTS 逐个呼叫 + ASR 识别回应 + 虚拟形象配合 | 1.5天 |
| 声纹标注发言人 | ASR 转写 + 声纹识别 → Web 页面实时显示 | 0.5天 |
| 飞书会后交付 | 纪要/待办/统计 自动推送（待办推送至具体责任人） | 1天 |

### V1.2 — 会控增强：到期确认与自动延时（下一版本）

**目标**：在「不自动下一议题、不自动结束会议」前提下，**仅当前议题**预设时长耗尽时由发起人明确选择是否结束本议题；若继续讨论则对**该议题**自动延时，减少反复改模板或手动改钟的操作。**会议总时长**到点的询问与总倒计时延时 **本期不做**。

| 功能 | 说明 | 工作量（预估） |
|------|------|--------------|
| 议题到期交互 | TTS 引导 + Web 确认「结束本议题 / 继续」；与现有倒计时状态机衔接 | 0.5～1 天 |
| 自动延时逻辑 | 延长当前议题结束时刻；步长、最大次数、超时默认策略可配置 | 0.5～1 天 |

**依赖**：V1.0 Web 会议页与议程状态机已稳定；TTS 播报队列需支持插入「确认类」话术且不与会中零飞书冲突（仍不向飞书推送）。

### V2.0 — 未来规划

## 九、风险与依赖

### 9.1 依赖项

| 依赖 | 状态 | 风险 |
|------|------|------|
| smart-meeting-java 框架 | ✅ 已具备 | 低 |

| Web 页面开发能力 | ✅ 现有框架已含前端 | 中：需新增虚拟形象展示+口型同步 |

| 议程模板格式 | ❓ 待阿统提供 | 中 |

### 9.2 风险项

| 风险 | 影响 | 应对 |
|------|------|------|
| TTS 语音自然度不够 | 用户体验打折 | 提供音色选择，降级为 Web 文字提醒 |
| 虚拟形象口型同步延迟大 | 体验不自然 | 优先保证延迟 ≤ 200ms，超阈值降级为静止形象 |

| 虚拟形象恐怖谷效应 | 用户不适 | 保持卡通/简洁风格，避免过度拟真；支持关闭 |
| Web 页面兼容性 | 部分浏览器/设备异常 | 适配 Chrome/Edge/Safari 主流版本 |
| 自动延时拖堂（V1.2） | 会议不可控延长 | 最大次数上限 + 超时默认策略可配置；可选仅允许发起人操作 |
