# 会前流程编排指南（零基础版）

适用对象：不会写代码、只会在管理后台点按钮的会务同学。  
目标：在 `meeting-admin-server` 后台，把“会前 24 小时”和“会前 10 分钟”两套会议工作流配置出来，并稳定运行。

> 版本说明（2026-05 最新）：  
> 1) `pre-agenda-owner-confirm-notify` 已支持 **按 `presetTypeCode` 直接触发**（不依赖会议）；  
> 2) 其他步骤仍是 **meeting 维度执行**；  
> 3) 流水线页面已支持 **删除模板/删除步骤**。

---

## 1. 你将得到什么

完成本指南后，你可以在后台实现：

- 会前 24 小时自动做“资料提醒、议题通知、声纹检查”
- 会前 10 分钟自动做“参会确认、会前盘点”
- 会前收集“会序资料回填”（个人/群/混合通知都可）
- 会议结束后自动进入会后流程（POST）
- 需要人工确认的环节会进入 `WAITING_CALLBACK`，等待按钮回调后继续

## 2. 先准备（5 分钟）

### 2.1 登录后台

1. 打开：`http://127.0.0.1:8766/admin`
2. 使用管理员 token 登录（`X-Admin-Token`）
3. 左侧进入 `流水线编排`（`#/pipeline`）

### 2.2 确认系统已启用自动触发

请让技术同事确认以下配置已生效（你只需核对结果）：

- `meeting.scheduler.pre-enabled=true`
- `meeting.scheduler.pre-24h-template-code=pre_24h_default`
- `meeting.scheduler.pre-10m-template-code=pre_10m_default`
- `meeting.pipeline.post-auto-trigger.enabled=true`

> 看不懂没关系：只要技术同事回复“已按文档配置”，你就可以继续后续步骤。

---

## 3. 先理解三个词（非常重要）

- **模板**：一整套流程（例如“会前 24h 流程”）
- **步骤**：模板中的一个动作（例如“发议题通知”）
- **阶段**：
  - `PRE` = 会前
  - `MID` = 会中（本期不做自动触发）
  - `POST` = 会后

你要做的是：创建两个 `PRE` 模板，然后往模板里按顺序加步骤。

---

## 4. 配置会前 24h 流程（模板一）

## 4.1 新建模板

在 `流水线编排` 页面点击 `新增模板`：

- `templateCode`: `pre_24h_default`
- `templateName`: `会前24小时标准流程`
- `stage`: `PRE`
- `enabled`: 勾选

保存后，点击该模板的 `新增步骤`。

## 4.2 推荐步骤顺序（24h）

按以下顺序新增：

1. `pre-push-doc-link`（附上次纪要）
2. `pre-agenda-notify`（通知本次议题）
3. `pre-voiceprint-check`（检查声纹是否就绪）
4. `push-notification`（补充一条通用提醒）

### 4.3 每个步骤的建议配置

#### 步骤 1：`pre-push-doc-link`

- `stepCode`: `pre24_doc_link`
- `stepName`: `推送上次纪要链接`
- `orderNo`: `1`
- `timeoutSeconds`: `120`
- `configJson`:

```json
{}
```

#### 步骤 2：`pre-agenda-notify`

- `stepCode`: `pre24_agenda_notify`
- `stepName`: `议题归集通知`
- `orderNo`: `2`
- `configJson`:

```json
{}
```

#### 步骤 3：`pre-voiceprint-check`

- `stepCode`: `pre24_voiceprint_check`
- `stepName`: `声纹就绪检查`
- `orderNo`: `3`
- `configJson`:

```json
{}
```

#### 步骤 4：`push-notification`

- `stepCode`: `pre24_general_remind`
- `stepName`: `会前通用提醒`
- `orderNo`: `4`
- `configJson`:

```json
{
  "targetType": "CHAT",
  "messageTemplate": "会前24小时提醒：请相关同事完成材料准备与参会确认。会议：{meetingTitle}"
}
```

## 5. 配置会前 10 分钟流程（模板二）

## 5.1 新建模板

- `templateCode`: `pre_10m_default`
- `templateName`: `会前10分钟冲刺流程`
- `stage`: `PRE`
- `enabled`: 勾选

## 5.2 推荐步骤顺序（10min）

1. `pre-confirm-card`（发“参加/请假”卡片）
2. `pre-confirm-persist`（把确认结果写入状态）
3. `pre-inventory-card`（会前盘点卡）
4. `pre-key-decliner-alert`（关键人请假提醒负责人）

### 5.3 每个步骤建议配置

#### 步骤 1：`pre-confirm-card`

```json
{
  "title": "会议参会确认（会前10分钟）",
  "body": "请点击按钮确认是否参加本次会议。"
}
```

> 该步骤会进入 `WAITING_CALLBACK`，等待用户点击按钮。

#### 步骤 2：`pre-confirm-persist`

```json
{}
```

#### 步骤 3：`pre-inventory-card`

```json
{}
```

#### 步骤 4：`pre-key-decliner-alert`

```json
{
  "keyUserIds": ["feishu_user_id_key_a", "feishu_user_id_key_b"]
}
```

> `keyUserIds` 是关键参会人列表，需要技术或管理员提供正确的 `user_id`。

### 5.4 可选增强：会序资料回填（个人/群/混合）

如果你只想“到指定时间给会序负责人发确认通知，并允许负责人改会序”，优先用一个步骤：

1. `pre-agenda-owner-confirm-notify`

示例：

```json
{
  "entryUrl": "https://oa.qdyhjz.cn/meeting-server/agenda-fill.html",
  "expireMinutes": 180,
  "leaderUserIds": ["feishu_user_id_leader"],
  "userMessageTemplate": "请确认并完善你负责的会序：{fillUrl}\n会议：{meetingTitle}"
}
```

说明：

- 自动识别收件人：`preset.host_agenda.items[].owners`
- 自动下发个人可编辑链接
- 在“按 `presetTypeCode` 直触发”模式下，提交后更新的是**预设会序**（preset）
- `leaderUserIds` 可编辑全部授权项（兜底负责人）
- 同时会自动读取模板 `leader_name`：
  - meeting 模式：按“本次会议参会人”唯一匹配 leader
  - preset 直触发模式：使用 `leader_name` 作为兜底 leader 标识（建议同时在 `leaderUserIds` 明确填写可操作人）

---

如果你要在会前让不同同事补齐“会序 URL + 时长（分钟）”，在 PRE 模板里新增这两步：

1. `pre-agenda-fill-init`
2. `pre-agenda-fill-notify`

建议放在 `pre-agenda-notify` 后面。

**步骤 A：`pre-agenda-fill-init` 示例**

```json
{
  "presetCode": 1,
  "expireMinutes": 180,
  "leaderUserIds": ["feishu_user_id_leader"]
}
```

说明：

- 会序负责人从 `host_agenda.items[].owners` 自动识别（可空、可多个）
- `leaderUserIds`：负责人，可编辑全部授权项
- 系统会为每个人自动生成专属 token

`host_agenda` 负责人字段示例：

```json
{
  "version": 2,
  "items": [
    { "title": "会序1", "minutes": 10, "owners": ["feishu_user_id_owner_a"] },
    { "title": "会序2", "minutes": 5, "owners": ["feishu_user_id_owner_b", "feishu_user_id_owner_c"] }
  ]
}
```

**步骤 B：`pre-agenda-fill-notify` 示例（混合发送）**

```json
{
  "entryUrl": "https://oa.qdyhjz.cn/meeting-server/agenda-fill.html",
  "sendParticipantUsers": true,
  "groupClaimCard": true,
  "groupInlineFillCard": false,
  "groupIds": ["oc_xxx_group_a"],
  "fallbackMeetingChat": true,
  "extraUserIds": ["feishu_user_id_ops"],
  "userMessageTemplate": "请在会前完成你负责会序资料回填：{fillUrl}",
  "groupMessageTemplate": "会前会序资料回填已发起，请相关同事打开个人通知中的回填链接完成提交。"
}
```

说明：

- **个人发送**：`sendParticipantUsers=true`
- **群发送**：`groupIds` 或会议群兜底 `fallbackMeetingChat=true`
- **按人动态发链接**：`groupClaimCard=true` 时，群里只发“领取我的回填链接”按钮；点击后系统按当前点击人自动私聊其专属 token 链接
- **群内直接填（不跳转）**：`groupInlineFillCard=true` 时，群里直接出现输入框（会序编号/分钟/URL），提交后即时回填
- **混合发送**：两者同时配置即可
- 回填页面入口：`/meeting-server/agenda-fill.html?token=...`
- 回填提交默认更新**当前会议**会序

## 6. 给步骤加“条件执行”（可选）

你可以让某些步骤只在满足条件时执行。

示例：仅当会议状态是 `INVITED` 才执行：

```json
{
  "condition": {
    "key": "meeting.status",
    "equals": "INVITED"
  }
}
```

把这段放进对应步骤的 `configJson` 即可。

## 7. 如何测试（非常推荐）

每次改完模板，都做一次人工测试：

1. 在 `流水线编排` 页面找到 `触发执行`
2. 触发参数按下面规则填写：
   - `pre-agenda-owner-confirm-notify`：优先输入 `presetTypeCode`（可直接触发，不依赖会议）
   - 其他步骤：输入 `meetingId`（单场执行）
3. `stage` 选 `PRE`
4. `templateCode` 填 `pre_24h_default` 或 `pre_10m_default`
5. 点击 `执行`
6. 查看下方“最近执行记录”

看结果时重点关注：

- `SUCCESS`：通过
- `WAITING_CALLBACK`：等待卡片按钮回调（正常）
- `FAILED`：某步骤失败，点开详情看 `lastError`
- `TIMEOUT`：超时，通常是回调没回来或外部接口失败

## 8. 上线前检查清单（按顺序）

1. 两个 PRE 模板都 `enabled`
2. 步骤顺序正确（orderNo 从小到大）
3. `pre_24h_default`、`pre_10m_default` 与系统配置一致
4. 随机抽 1 个测试会议手动跑通
5. 会前卡片能正常回调（`WAITING_CALLBACK` 能变为 `SUCCESS`）
6. 会议结束后能看到 POST 自动触发记录

## 9. 常见问题（不会技术也能判断）

### Q1：我配置了模板，但没有自动执行？

优先检查：

1. 模板是否 `enabled`
2. `templateCode` 是否和系统配置一致
3. 会议是否有 `scheduledTime`
4. 会议时间是否落在触发窗口（24h/10min）

### Q2：一直卡在 `WAITING_CALLBACK`？

说明流程在等用户点卡片按钮。请检查：

1. 卡片是否成功发出
2. 用户是否已点击
3. 飞书回调地址/token 是否正确（找技术同事）

### Q3：我只想临时停用某一步？

在步骤详情里把该步骤设为“停用”即可，不用删模板。

### Q4：会中流程为什么不自动跑？

这是当前策略：会中（MID）暂时保留人工控制，避免影响会议现场节奏。

### Q5：为什么我填了 `presetTypeCode`，但有些步骤没执行？

当前版本里，`presetTypeCode` 直触发主要用于 `pre-agenda-owner-confirm-notify`。  
如果模板里没有该步骤，或你希望执行其它 PRE/MID/POST 步骤，请改用 `meetingId` 触发。

### Q6：模板或步骤配错了怎么回滚？

`#/pipeline` 页面已支持：

- 删除模板（会同时删除该模板下步骤）
- 删除步骤（仅删除当前步骤）

删除前有二次确认提示。

## 10. 给管理员的“默认模板速用版”

如果你时间很紧，直接按下列最小可用配置：

- `pre_24h_default`：
  - `pre-push-doc-link`
  - `pre-agenda-notify`
  - `pre-voiceprint-check`
- `pre_10m_default`：
  - `pre-confirm-card`
  - `pre-confirm-persist`
  - `pre-inventory-card`
- POST 自动触发开启，模板使用默认 POST 启用模板

这样就能先跑起来，再逐步细化。

---

## 11. 最新推荐触发口径（避免误用）

- **会序确认（owner-confirm）**：用 `presetTypeCode`（code 维度）
- **其他流程步骤**：用 `meetingId`（meeting 维度）
- **会前自动触发（24h/10m）**：继续走调度器
- **会后自动触发（POST）**：继续走结束事件自动触发
