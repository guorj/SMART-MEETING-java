# 智能会议系统 - 开关手册

文档版本：2026-05-31  
适用范围：`meeting-server`（`application.yml` + profile 覆盖 + 环境变量覆盖）

---

## 1. 目标与原则

本手册用于统一说明系统中可配置开关（feature flags / runtime toggles）：

- 已实现：可直接通过 yml / 环境变量生效。
- 建议新增：尚未落地，仅做运维与研发规划，不代表当前版本可用。

开关设计原则：

- 同一能力尽量“主开关 + 细分开关”。
- 对外部依赖（飞书、LLM、ASR）优先提供降级开关。
- 对定时任务优先提供 `enabled` 开关，避免误触发。

---

## 2. 配置生效优先级

Spring Boot 常规优先级（高 -> 低）：

1. 环境变量（如 `MEETING_TODO_REMINDER_ENABLED`）
2. profile 配置（如 `application-dev.yml`、`application-prod.yml`）
3. 默认配置 `application.yml`

说明：

- 大部分开关改动后需要重启服务生效。
- 使用 `@ConditionalOnProperty` 的组件（如定时任务）必须重启后才会注册/反注册。

## 3. 已实现开关（当前可用）

## 3.1 会后链路

| 配置键 | 默认值 | 作用 | 影响范围 |
|---|---|---|---|
| `meeting.minute.generation-enabled` | `false` | 会后是否生成纪要主链路 | 关闭后不触发 `MeetingEndedEvent` 纪要处理 |
| `meeting.minute.persist-enabled` | `true` | 是否落库纪要正文 | 关闭后仅保留外链/状态 |
| `meeting.minute.expose-content-in-api` | `true` | 纪要 API 是否返回全文 | 关闭后 API 仅返回元信息 |
| `meeting.minute.ai-enhancement-enabled` | `true` | 纪要 AI 增强开关 | 关闭后仅保留初稿 |
| `meeting.todo.extraction-enabled` | `false` | 是否执行待办提取链路 | 关闭后不发布/不执行待办提取 |
| `meeting.todo.reminder-enabled` | `false` | 待办提醒定时任务总开关 | 关闭后不注册 `TodoReminderScheduler` |

补充：

- `meeting.todo.reminder-cron` 当前仍可配置执行周期；仅在 `reminder-enabled=true` 时生效。

## 3.2 调度与编排

| 配置键 | 默认值 | 作用 |
|---|---|---|
| `meeting.scheduler.pre-enabled` | `true` | 会前 PRE 自动触发总开关 |
| `meeting.scheduler.pre-window-minutes` | `5` | PRE 触发容忍窗口 |
| `meeting.scheduler.pre-24h-template-code` | 空 | 会前 24h 模板 |
| `meeting.scheduler.pre-10m-template-code` | 空 | 会前 10min 模板 |
| `meeting.scheduler.scan-ms` | `300000` | PRE 扫描周期（毫秒） |
| `meeting.pipeline.post-auto-trigger.enabled` | `true` | 会后 POST 自动触发开关 |
| `meeting.pipeline.post-auto-trigger.template-code` | 空 | POST 指定模板编码 |
| `meeting.cache.refresh-enabled` | `true` | 预设缓存定时刷新开关 |
| `meeting.cache.refresh-cron` | `0 */10 * * * ?` | 预设缓存刷新 Cron |

## 3.3 中台能力与外部依赖

| 配置键 | 默认值 | 作用 |
|---|---|---|
| `meeting.kafka.enabled` | `false` | Kafka / LocalEventBus 双形态切换 |
| `meeting.audio.cloud-download-enabled` | `true` | 会后是否允许云端录音下载兜底 |
| `meeting.asr.realtime-enabled` | `false` | 会中实时转写开关 |
| `meeting.host.enabled` | `true` | AI 主持总开关 |
| `meeting.host.agenda-enabled` | `true` | 主持会序推进能力 |
| `meeting.host.tts-enabled` | `true` | 主持 TTS 开关 |
| `meeting.host.roll-call-enabled` | `true` | 混合检点开关 |
| `meeting.host.auto-roll-call-after-opening` | `true` | 开场后自动检点开关 |
| `meeting.notification.bot-enabled` | `false` | 会后通知走 scheduled-bot 网关 |

## 4. 已有定时任务与开关现状

| 任务类 | 触发配置 | 当前是否有 `enabled` |
|---|---|---|
| `TodoReminderScheduler` | `meeting.todo.reminder-cron` | 是（`meeting.todo.reminder-enabled`） |
| `PresetCacheRefreshScheduler` | `meeting.cache.refresh-cron` | 是（`meeting.cache.refresh-enabled`） |
| `MeetingScheduler` | `meeting.scheduler.scan-ms` | 部分（逻辑内 `pre-enabled`） |
| `RecordingSilenceAutoPauseScheduler` | 固定 60s | 否（仅通过 `silence-auto-pause-min<=0` 近似关闭） |
| `RecordingTimeoutChecker` | 固定 5 分钟 + 每小时 | 否 |
| `AudioCacheCleaner` | 固定凌晨 3 点 + 周报 | 否 |
| `OutboxPoller` | `meeting.outbox.poll-delay-ms` | 否 |
| `PipelineTimeoutScanner` | `meeting.pipeline.timeout-scan-ms` | 否 |

## 6. 推荐运维组合

## 6.1 “只保留会中录音，不做会后”场景

```yaml
meeting:
  minute:
    generation-enabled: false
  todo:
    extraction-enabled: false
    reminder-enabled: false
```

## 6.2 “保留纪要，不要待办提醒”场景

```yaml
meeting:
  minute:
    generation-enabled: true
  todo:
    extraction-enabled: true
    reminder-enabled: false
```

## 6.3 生产安全降载（建议）

- 明确设置每个关键开关，不依赖默认值。
- 所有 `enabled` 配置在 `application-prod.yml` 显式声明并留注释。
- 发布后核对一次启动日志，确认关键 Scheduler 注册状态与预期一致。

---

## 7. 变更流程建议

1. 先更新本手册（记录新增/废弃开关）。  
2. 再做代码实现。  
3. 同步更新 `application.yml` / `application-dev.yml` / `application-prod.yml` 示例值。  
4. 发布前执行一次“开关矩阵验证”（至少覆盖 dev/prod 两套组合）。
