### 1.3 架构偏差（PRD vs 实现）

| 维度 | PRD 设计 | 实际实现 | 影响 |
|------|----------|----------|------|
| Web 框架 | Spring WebFlux | Spring MVC + WebSocket | 中小并发可接受 |
| 模块化 | 多子模块 | 单模块 `meeting-server` | 维护与边界清晰度 |
| 定时调度 | XXL-Job | `@Scheduled` | 多实例可能重复执行 |
| 状态机 | 显式状态机类 | 分散在 Service | 需靠测试与评审保证合法迁移 |

## 二、最终产品形态预判

### 2.1 2 个月节点（约 8 周）—— 生产可用的闭环 MVP

**定位**：企业内部可正式上线使用的「会中智能记录 + 会后闭环」为主；会前仍以飞书指令/卡片快速路径为主。

**能力边界（目标态）**：

- 飞书机器人：创建/开始/结束、录音链接、纪要卡片、待办与进度相关交互补齐 stub。
- 录音页：实时 ASR、主持页 TTS/议程/点名、断线重连与补传（按周落地）。
- 会后：声纹或规则化说话人写回、纪要+文档、待办提取、临期提醒与延期标记、配置与密钥外置。

**量化目标（建议验收口径）**：

- 多场并发会议稳定（例如 10 场量级压测通过）。
- 会议结束到纪要可见：目标 ≤10 分钟（含 LLM 排队波动）。
- 待办提醒与状态闭环可用。

### 2.2 6 个月节点（约 24 周）—— 企业级三阶段闭环平台

**定位**：对齐 `docs/PRD-Java-一期.md` / 二期与 AI 主持人 PRD 的 P0/P1 为主，补齐会前筹备、飞书日历/任务、运维与可观测性。

**能力边界（目标态）**：

- 会前：议题收集、参会确认、议程推送、邀约与日程（按资源投入分阶段）。
- 会中：AI 主持人完整版（会前盘点、点名、虚拟形象、议题延时策略等按优先级取舍）。
- 会后：待办与飞书任务同步、看板、手动修正与重生成、分布式调度与监控告警。

## 四、所需资源

### 4.1 人力（建议）

| 角色 | 人数 | 职责 |
|------|------|------|
| 后端（Java/Spring Boot） | 1–2 | 业务、WebSocket、MQ、定时、飞书服务端 |
| 前端（静态页 + JS） | 0.5–1 | 录音页、主持页、看板 |
| 飞书对接 | 0.5 | 日历、任务、卡片与权限 |
| DevOps | 0.5 | 部署、监控、CI/CD |
| 产品/测试 | 0.5 | 验收与文档 |

**最小团队**：1 名偏全栈的后端 + 0.5 前端。  
**推荐团队**：2 后端 + 1 前端 + 0.5 运维。

### 4.2 基础设施（量级参考）

| 资源 | 用途 |
|------|------|
| 4C8G 云主机（或等价） | 应用 + Nginx |
| MySQL 8 | 业务库 |
| Redis | Token、会话、延时提醒等 |
| Kafka（可选） | 与现有 `meeting.kafka.enabled` 策略一致；小规模可用 LocalEventBus |
| 域名与 TLS 证书 | 录音页麦克风权限 |

### 4.3 第三方与成本量级

- 讯飞：实时 ASR、离线 ASR、ISV、TTS（按量计费，与会议时长与调用次数强相关）。
- 大模型：DeepSeek 等（纪要 + 待办 + 纠错，token 量相对可控）。
- 飞书开放平台：按官方配额与版本。

具体金额随场次、时长、模型选型变化，建议在试点阶段拉取账单做月度预估。

## 五、核心难点与风险

### 5.1 技术难点

| 难点 | 说明 | 应对 |
|------|------|------|
| 声纹与转写闭环 | 注册 feature、实时 feature_ids、离线识别、写回 transcript、纪要引用一致 | 分阶段：先会后批量识别，再实时映射；保留盲分与人工修正 |
| WebSocket 与音频完整性 | 断线、抖动、补传顺序 | 帧序号、服务端去重、PCM 文件兜底 |
| 主持会话状态机 | 议程、TTS 队列、点名、静音注册交织 | 单测 + 集成测试；必要时引入显式状态机库 |
| 飞书卡片 1s 响应 | 异步处理与幂等 | 保持现有异步模式；回调幂等键 |

### 5.2 产品与交付风险

| 风险 | 说明 | 应对 |
|------|------|------|
| 会前流程过重 | 用户仍习惯「一句话开会」 | 保留快速路径；会前能力作为可选增强 |
| 声纹渗透率低 | 说话人仍多为 speaker_n | 会前提醒注册；飞书侧修正与再生纪要 |
| 多实例部署 | `@Scheduled` 重复 | 上 XXL-Job 或分布式锁 |
| 密钥与配置 | 仓库内明文配置的历史包袱 | 全部迁环境变量/密钥管理；轮换密钥 |

## 六、总结

- **当前代码**：会中主链路（录音、实时 ASR、纪要、飞书文档、待办提取、Kafka/本地事件、AI 主持人后端）已较完整；**声纹写入纪要管线、腾讯降级、会前状态机、提醒 ZSet、飞书任务/日历、企业级安全与调度**等与 PRD「全闭环」仍有差距。
- **约 2 个月**：聚焦「可上线闭环 MVP」——声纹/离线校正、提醒与飞书交互 stub、安全与部署、稳定性压测。
- **约 6 个月**：在人力允许前提下，向 PRD 企业级三阶段 + AI 主持人完整版靠拢，并按优先级做减法，避免无限范围。
